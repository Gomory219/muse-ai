## 现在后端的聊天记录的存储，以及对话SSE返回的结果有所改变：

### 聊天记忆：在进入应用生成界面时会调用后端接口获取

1. 现在后端一共有三种聊天信息，以下是其枚举定义：

```java
public enum MessageTypeEnum {
    USER,
    AI,
    TOOL_EXECUTED;
}
```
2. 当聊天信息为USER时，处理的方式和之前一样。
3. 当聊天信息为AI时，多了一个toolExecutionRequests属性，他是一个对象数组，以下是其实体定义：只不过没有toolOutput，你只需要展示剩下的三个即可
    - 拿到AI消息后，首先展示消息内容。
    - 然后展示AI对工具的请求，包括：工具名称和工具的参数，注意，这个是一个数组，可能有多个。下面是一个例子：

### 对话SSE返回JSON


1. 以下是Java相关实体定义：

```java
@Data
@Builder
public class StandardMessage {
    /**
     * 消息类型
     */
    private JsonViewType jsonViewType;
    /**
     * 消息内容
     */
    private String v;
    /**
     * 工具名称
     */
    private String toolName;

    /**
     * 工具执行结果
     */
    private String toolResult;

    public static StandardMessage finishMessage() {
        return StandardMessage.builder()
                .jsonViewType(JsonViewType.FINISH)
                .build();
    }
}

public enum JsonViewType {
    TEXT,
    FINISH,
    TOOL_REQUEST,
    TOOL_EXECUTED
}

```
2. 共有4种消息类型，根据jsonViewType来判断
    - 当 TEXT 时，读取实体中的`v`属性，则为正常的ai生成聊天信息，和之前一样流式输出到聊天框即可。
    - 当为 FINISH 时，不用管其他的属性，标志着后端正常结束。
    - 当为TOOL_REQUEST时，则为AI申请调用工具。此时你应该在前端的聊天框中以一些组件显示这条记录，需要包括的信息有：toolName:工具名称。
    - 当为TOOL_EXECUTED时，则为AI调用工具结束。此时你应该在前端的聊天框中以另外一些组件显示这条记录，需要包括的信息有：toolName:工具名称，toolResult:工具执行结果以及v:工具参数



### 注意：
1. 虽然都是工具调用申请和工具调用结果，在请求聊天记录时参数位于 《工具申请》中， 在AI返回时参数位于《工具调用》中，请你区分
